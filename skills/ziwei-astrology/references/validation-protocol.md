# 验前事校验协议

> 灵感来源：vedic-astro-skills 的验前事校验机制（past-validation），适配紫微斗数体系重写。

## 目的

排盘成功后、生成报告前，用固定4条可证伪的事实性预测校准命盘可信度。若时辰有误，整份报告可能全部跑偏——验前事是唯一的"排盘正确性守门员"。

## 触发时机

排盘成功后（Step 2完成）、格局识别前（Step 3之前），即 Step 2.5。

## 推导规则

### 从哪里推导

只从 `chart-data.json`（iztro排盘数据）推导，不使用对话中用户透露的任何背景信息。

### 推导什么

固定4条**可证伪的事实性预测**，优先从以下信号推导：

| 信号来源 | 可推导的验前事类型 | 示例 |
|---------|------------------|------|
| 命宫主星+亮度 | 性格核心特征 | "你做事比较果断，不喜欢拖泥带水" |
| 迁移宫 | 是否离开家乡发展 | "你应该离开出生地发展了" |
| 夫妻宫+福德宫 | 感情模式 | "你感情上比较晚熟，早婚不利" |
| 过去大限（已走过的） | 人生阶段事件 | "2015-2024这十年，你事业上有比较大的变动" |
| 父母宫 | 与父母关系 | "你跟父亲的关系比较疏远" |
| 兄弟宫 | 手足情况 | "你应该不是独生子" |

### 推导强度分级

| 级别 | 条件 | 推导方式 |
|------|------|---------|
| A级强信号 | 主星庙旺/化忌/参与格局的星 | 可做明确断语 |
| B级中信号 | 主星平/辅星会照 | 做倾向性断语，加"可能""倾向" |
| C级弱信号 | 无主星/仅杂耀 | 不用于验前事 |

### 推导格式

每条验前事必须包含：

```
【验前事 N】{断语}
  信号来源：{宫位} {星曜} {状态}
  推导强度：{A/B}级
  可证伪性：{如何证明准或不准}
```

示例：

```
【验前事 1】你应该离开出生地发展了
  信号来源：迁移宫 太阳庙旺
  推导强度：A级
  可证伪性：是否在异地工作/生活

【验前事 2】你感情上比较晚熟，早婚不利
  信号来源：夫妻宫 武曲+化忌
  推导强度：A级
  可证伪性：是否晚婚或感情经历波折

【验前事 3】2015-2024这十年，你事业上有比较大的变动
  信号来源：第3大限 大限宫干化忌冲官禄宫
  推导强度：B级
  可证伪性：该十年是否有职业变动
```

## 用户反馈处理

### 收集方式

前端会进入结构化提问模式：一次只回答当前题，提供5个固定选项：`很不准 / 不太准 / 一般 / 比较准 / 很准`，分别计 `1 / 2 / 3 / 4 / 5` 分。用户逐题点击并提交，最后一题确认后统一计算总分；可选备注会随最终提交一并发送，不需要额外解释原因。

### 评分计算

总分 = 4题分数相加，满分20分。

### 可信度判定

| 总分 | 可信度 | 后续处理 |
|------|--------|---------|
| 13-20 | 可继续 | 继续生成完整报告 |
| 1-12 | 偏低 | 直接拦截报告，提示先确认出生时辰或做时辰校准 |

### 反馈硬约束

当用户给出低分时：

1. **禁止改换说法重新解释**（"其实从另一个角度..."）
2. **禁止降低精度后重新匹配**（"那大概在附近区域..."）
3. **禁止顺着用户的话复述**（"是的，所以其实..."）
4. **必须直接接受"不准"**，计入评分，不追加解释
5. **唯一允许的追问**："您的出生时辰确认是XX时吗？"

### 安全约束

1. 只有一轮验前事，不追加第二轮——越猜越错
2. 不能用用户反馈的信息"装作"独立推断
3. 不追加新预测来"弥补"未命中的条目
4. 验前事提到的用户个人信息不能用于生成报告结论

### 反敌意用户防御

当用户对验前事结果表达强烈不满时：

| 用户说 | 回应 |
|--------|------|
| "都不准还分析什么？" | "这一步验证的是时辰精度。完整分析同时交叉多个维度，和单点检测的精度完全不同。" |
| "准的也是蒙的吧？" | "每条推断都附了推导——宫位+星曜+大限对应，是确定性推导。" |
| "你说XX年我是YY年" | "时间偏差已记录。" ← 不展开解释 |
| "我不想继续了" | "完全理解。完整分析在下一步，随时说'继续'。" |

硬规则：
1. 不为未命中条目道歉——它是诊断信息不是失败
2. 不逐条解释为什么没命中——一句带过
3. 未命中 = "记录"，重心立即转向"进入分析"

## 验前事复盘

> 灵感来源：vedic-astro-skills 的验前事复盘机制（past-validation review）。

完整报告生成后，如果验前事命中率<100%（即有任何未命中项），自动触发复盘：

### 触发时机

Step 4（生成报告）完成后、Step 5（继续提问）之前。

### 复盘内容

对每条标注"不准"的验前事，用完整分析结果回溯解释：

```
### ❌ 验前事第N条：[当初的推断]
当初推导：[信号来源+推导逻辑]
完整分析发现了什么：[更全面的分析结论]
偏差原因：[当初快速检测看了哪个信号 → 完整分析发现了什么更强/更准确的信号]
正确的解读应该是：[完整分析后的结论]

### ✅ 验前事第N条：[当初的推断]
推导正确，完整分析确认了这个信号。
```

### 复盘隔离规则

- 复盘只引用排盘数据和完整分析结论，不引用用户的具体个人经历
- 解释"错在哪"时只用盘面数据和分析结果
- 不引用用户的个人经历作为"证据"（保持盲审完整性）
- 复盘结论写入报告附录，聊天框简报一句

## 信号修正日志

验前事校准后，可记录**信号层面的规律**（不记录用户具体个人信息）：

```
信号修正日志：
- 迁移宫太阳庙旺→确认"离乡发展"表达方向
- 夫妻宫武曲化忌→确认"感情执念"表达方向
```

此日志仅辅助判断信号的表达方向，仍以排盘数据为主推导。

## 时辰校准流程

当可信度为"低"时，建议用户使用独立的 **time-calibration** skill 进行时辰反推。

**⚠️ 重要**：时辰校准不应在当前排盘分析对话中进行，应引导用户开启新对话使用 `time-calibration` skill。原因：
1. 校准过程需要用户透露人生经历，违反本 skill 的盲审原则
2. 校准过程中获取的信息不应影响后续命盘分析的客观性

**引导话术**：

```
验前事命中率较低，可能是出生时辰不太准确。
建议你开启一个新的对话，告诉我"我不知道自己几点出生的"，
我会通过反推时辰的流程帮你确定最可能的时辰。
确定后再回来排盘分析。
```

**校准后重新排盘的规则**：
- 用户必须在新对话中提供校准后的时辰
- 不得使用校准对话中获取的任何人生经历信息
- 重新排盘后仍需执行验前事校验

## 时间精度与分盘可信度

| 时间精度 | 可信度标注 | 分析深度 |
|---------|-----------|---------|
| 精确时辰 | ✅ | 完整分析 |
| 跨时辰边界（±30分钟） | ⚠️ | 大限/流年分析标注⚠️，本命盘正常 |
| 无时辰 | ❌ | 仅本命盘基础分析，大限/流年仅供参考 |
