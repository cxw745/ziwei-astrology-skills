# 紫微斗数排盘与命盘详析

基于两个开源仓库排盘与解读（已作为 `sources/` 子目录包含在项目中）：
- **iztro**（`sources/iztro/`）：排盘算法核心
- **ziwei-doushu**（`sources/ziwei-doushu/`）：倪海厦《天纪》体系知识库

冲突时以 ziwei-doushu（倪海厦体系）为准。

## 核心原则

1. **排盘必须调用代码**：手动推算极易出错，所有计算必须通过 iztro 的 `bySolar` 方法
2. **解读必须基于知识库**：所有断语必须来自 references 或 sources 文件，不确定的标注"无法确定"
3. **实事求是，拒绝讨好**：凶象如实描述，不弱化化忌影响，不强行凑格局
4. **三模式解读**：iztro标准 / 倪海厦天纪 / 综合（默认），冲突以倪师为准
5. **双层输出**：专业解读 + 通俗解析
6. **首次输出完整报告**：用户第一次提供信息时输出完整命盘报告，内容丰富度必须达到示例水平（1000行以上），不可省略任何章节或子节
7. **来源标注**：每条事实性内容必须标注来源文件，格式 `[来源: 仓库名/文件路径]`，详见 `references/source-repos.md`

## 星耀处理规范

- **空宫**：借对宫主星论断，力量减半，借星亮度以对宫为准
- **minorStars归属**：文曲、禄存、天马等属辅星，即使有四化也放辅星列
- **借星共存**：借星与本宫实坐星曜共存时需同时分析

## 三模式解读

| 模式 | 数据来源 | 亮度 | 大限四化 |
|------|---------|------|---------|
| [iztro] | iztro数据 | 七级 | 使用 |
| [倪师] | 倪师知识库 | 三级（庙旺/平/陷） | 不使用 |
| 综合（默认） | 两体系综合 | 双标注 | 标注差异 |

亮度映射：庙旺→庙旺，得利平→平，不陷→陷

综合模式冲突处标注"[iztro]xxx / [倪师]xxx，以倪师为准"。

HTML界面体系切换：工具栏按钮或键盘1/2/3切换，正文内容实时变化。

## 输出文件规范

**重要**：所有输出保存在用户工作目录下的 `ziwei-output/`，不写入 skills 目录。

```
ziwei-output/{日期_HHmm}_{出生信息}/
├── 命盘详析.md / .html
├── {专项解读}.md / .html
├── 大限/第N大限_{年龄}.md / .html
├── 流年/{YYYY}年{干支}.md / .html
├── 流月/{YYYY}年{MM}月.md / .html
└── 合盘_{乙方信息}.md / .html
```

**命名规则**：`{日期_HHmm}` 为排盘时刻的日期+时分（24小时制），格式 `YYYY-MM-DD_HHmm`，如 `2026-05-22_1430`。精确到分钟确保同一生辰在不同时刻排盘时保存到不同文件夹，不会覆盖之前的报告。

所有专项解读同时生成 .md 和 .html。HTML 转换命令：
```bash
node scripts/md2html.js <input.md> [output.html]
```

完成后必须附加提示语，告知文件位置和可用快捷指令。模板见 `references/report-template.md`。

## 功能模块

| 模块 | 触发条件 | 输出 |
|------|---------|------|
| 单人排盘 | 出生日期+时辰+性别 | 完整十一章节报告 |
| 合盘分析 | `\match` + 另一半出生信息 | 合盘五步法+五星匹配度 |
| 流年解读 | 特定年份 | 四化+宫位交互+四维运势 |
| 择日择时 | 结婚/搬家/开业等 | 推荐吉日+理由+局限性 |
| 继续提问 | 基于已排命盘追问 | 复用数据不重新排盘 |

合盘分析参照 `references/heming-knowledge.md`，核心：看婚姻必须同时看福德宫。

`\match` 合盘分析流程：
1. 用户输入 `\match` 后，提示提供另一半的出生日期、时辰、性别（允许同性恋）
2. 分别为双方排盘（调用 iztro `bySolar`）
3. 按倪师合盘五步法分析：①评估双方命格基础 ②夫妻宫互参 ③太阳太阴星象分析 ④四化飞化互参 ⑤大限同步分析
4. 判断天作之合/次级良配/凶兆组合
5. 给出五星匹配度评级
6. 生成合盘报告（MD+HTML双格式），保存到 `ziwei-output/{日期_HHmm}_{甲方信息}_合盘_{乙方信息}/`

## 知识准备与补充策略

### Step 0：知识准备（按需加载）

排盘前不强制读取任何文件。但在以下环节必须回源验证：
- 格局判断 → 必须对照 `sources/ziwei-doushu/lib/ziwei/patterns.ts`
- 倪师断语 → 必须对照 `sources/ziwei-doushu/lib/nihai/tianji.ts`
- 古籍引用 → 必须对照 `sources/ziwei-doushu/lib/classics/data/`
- 四化数据 → 必须对照 `sources/iztro/src/data/heavenlyStems.ts`
- 亮度数据 → 必须对照 `sources/iztro/src/data/stars.ts`
- 星曜宫位断语 → 速查 `references/star-palace-matrix.md`，验证回源 `sources/ziwei-doushu/lib/seo/knowledge.ts`

### 网页搜索补充策略

当 references/ 和 sources/ 中的知识不足以完整回答用户问题时，可使用网页搜索补充。

**搜索原则**：
1. **仓库优先**：两个仓库内容为主，搜索结果为辅
2. **冲突处理**：搜索结果与仓库内容冲突时，以仓库为准
3. **来源标注**：搜索补充的内容标注 `[来源: 网络搜索]`，不与仓库来源混淆
4. **可信度筛选**：优先搜索学术文献、经典注疏、专业论坛，避开营销内容

**推荐搜索策略**：

1. 搜索关键词模板：`"紫微斗数" + "{星名}" + "{宫名}" + "倪海厦"`
2. 优先搜索站点：
   - 豆瓣读书（古籍注疏书评）
   - 知乎专业答主（紫微斗数话题）
   - 国学导航（经典文献在线）
   - 倪海厦相关学术论坛
3. 搜索结果可信度排序：古籍原文 > 学术论文 > 专业论坛 > 个人博客 > 营销内容
4. 搜索结果与仓库冲突时，一律以仓库为准，并在报告中标注差异

**搜索触发条件**：
- 某颗星在特定宫位的详细断语，仓库中无对应条目
- 用户追问的专业术语，仓库中未解释
- 特定流年的重大天象或社会背景
- 古籍原文的精确引用

**禁止搜索的场景**：
- 排盘计算（必须用 iztro 代码）
- 四化对照表（仓库已有完整数据）
- 格局判断规则（以仓库为准）
- 亮度数据（以仓库为准）

### 排盘失败降级方案

若 iztro 代码执行失败：
1. 尝试 `npm install iztro` 后重试
2. 若仍失败，基于 references/ 中的安星规则手动推算
3. 手动推算的报告必须标注"⚠️ 手动推算，未经代码验证，可能存在误差"
4. 手动推算时必须对照 sources/iztro/ 逐步验证

### 来源标注决策树

1. 数据来自 iztro 排盘结果 → `[来源: iztro排盘]`
2. 断语来自 references/ → 追溯到 sources/ 具体文件 → `[来源: 仓库名/文件路径]`
3. 断语来自 sources/ 直接阅读 → `[来源: 仓库名/文件路径]`
4. 断语来自网页搜索 → `[来源: 网络搜索]`
5. 无法追溯来源 → 标注"AI推断"

## 工作流

### Step 1：收集输入

提取：阳历日期、时辰（→索引）、性别、功能类型、解读模式。

时辰映射见 `references/time-mapping.md`。用户只给日期没给时辰时必须提示补充。

时辰模糊处理：
- 用户说"下午2点左右"等模糊时间 → 先按最可能时辰排盘，同时告知"时辰为XX时，若实际出生时间跨时辰边界，结果可能不同"
- 提供相邻时辰对比：列出关键差异点（命宫位置是否变化、主星是否不同、四化是否改变）
- 若相邻时辰导致命宫位置变化，必须明确告知用户"XX时与XX时命宫不同，请确认准确出生时间"

### Step 2：执行排盘

```typescript
import { astro } from 'iztro';
const result = astro.bySolar('YYYY-M-D', hourIndex, gender, true, 'zh-CN');
```

### Step 3：格局识别

参照 `references/patterns.md`，每个格局判断三层：必须条件（缺一不可）、加分项、破格条件。

### Step 4：生成报告

按 `references/report-template.md` 结构输出，根据解读模式生成对应风格。

**内容丰富度硬性要求**：
- 报告必须包含完整11章节，不可省略任何章节
- 十二宫分论必须全部12宫，每宫7个子节（主星/辅星/杂耀/飞化表/三方四正/长生/总评）
- 宫干飞四化总表必须完整（12宫×4化=48条）
- 五行局推算过程必须列出8步
- 命宫总论必须独立成章（6个子节）
- 四化飞化详析必须包含飞忌汇入/飞禄汇入统计
- 大限运势必须每个大限含表格+详细分析
- 流年要点必须5~7年含四化分析
- 综合建议必须7个子章节
- 附录不可省略（术语解释+亮度对照+参考文献）
- 倪师断语必须在每个关键宫位和四化处引用
- 报告内容丰富度以示例（examples/）为标准，不可省略任何子节

### Step 5：继续提问

复用已排命盘数据，不重新排盘。婚期判断必须遵循三层法（本命→大限→流年），详见 `references/report-template.md`。

### Step 6：核查（输出前必做）

1. 星耀位置与iztro排盘一致
2. 四化星名和落宫正确
3. 格局条件真正满足
4. 断语可追溯至references
5. 空宫正确借对宫
6. 身宫叠加正确
7. 来因宫正确
8. 无讨好倾向
9. **HTML完整性验证**：MD写入磁盘后，运行 `node scripts/md2html.js <input.md> [output.html]` 生成HTML，然后运行 `node scripts/validate-html.js <output_dir>` 验证HTML与MD内容对应完整，重点检查：
   - 十一章节全部存在于HTML中（一~十一）
   - 十二宫分论6.1~6.12全部存在于HTML中
   - HTML H2/H3数量与MD一致（差异≤2为正常）
   - HTML包含闭合标签`</body></html>`
   - MD中的自检清单、页脚声明在HTML中也存在
   - 若验证失败，重新运行md2html.js生成HTML

## 正反对比示例

以下示例帮助理解核心原则的具体应用。生成报告时必须参照正确示例，避免错误示例中的问题。

### 讨好倾向 vs 实事求是

❌ **错误**：虽然化忌入夫妻宫，但不必担心，只要用心经营就能化解，感情会越来越好的！
✅ **正确**：化忌入夫妻宫，主感情执念深、早婚不利。倪师断语"欠下婚姻债务"，建议晚婚（男30+，女27+），并需同时看福德宫判断婚姻能否长久。

❌ **错误**：命宫太阳庙旺，事业必然辉煌，一生大富大贵！
✅ **正确**：命宫太阳庙旺，主光明磊落、有助人之心，但太阳为散财星，需看财帛宫是否有守财之星配合，否则"赚多花多"。是否大富大贵还需看三方四正整体配合。

❌ **错误**：虽然七杀临身，但只要努力就能克服困难，反而能成就更大的事业！
✅ **正确**：七杀临身，倪师断语"七杀临身的人一辈子多败少成"。此为客观描述，非诅咒。知命而后能改——倪师强调"命是天注定的，运掌握在我们自己手上"，需通过阳宅调整、行业选择等方式化解。

### 格局判断 vs 凑格局

❌ **错误**：命宫紫微，三方有左辅会照，可论"君臣庆会格"，大富大贵！
✅ **正确**：君臣庆会格必须条件为"紫微入命+左辅右弼同会三方四正"，仅有左辅而无右弼，必须条件不满足，**不成格**。可描述为"紫微入命得左辅会照，有贵人助力，但缺右弼，未达君臣庆会格标准"。

❌ **错误**：命宫空宫，对宫有太阳太阴，这是"明珠出海格"，大富大贵！
✅ **正确**：明珠出海格必须条件为"命宫在未为空宫+对宫丑宫为太阳太阴同度"。若命宫不在未或对宫非丑宫日月同度，则不成格。空宫借星力量减半，不可过度拔高。

### 来源标注 vs 虚构来源

❌ **错误**：太阳在命宫庙旺，主大贵 [来源: iztro/src/data/stars.ts]
（如果此断语并非从stars.ts直接得出，而是AI综合分析）
✅ **正确**：太阳在命宫庙旺，主大贵 [AI综合分析]
（或追溯到实际来源：太阳庙旺于卯辰巳午 [来源: iztro/src/data/stars.ts]）

❌ **错误**：[来源: iztro/src/data/palace.ts]（此文件不存在）
✅ **正确**：只标注 sources/ 中实际存在的文件路径

### 体系混用 vs 体系标注

❌ **错误**：大限夫妻宫化禄，该十年感情运佳。（未标注这是飞星派做法）
✅ **正确**：大限夫妻宫见吉星会照，该十年感情有动。（倪师体系不使用大限四化，此处仅看星曜组合）

❌ **错误**：宫干自化忌，主该宫位自我消耗。（当作倪师体系断语）
✅ **正确**：宫干自化忌（※倪师体系不主张宫干自化，此处仅标注供参考），飞星派认为主该宫位自我消耗。

## ⚠️ 常见陷阱

- **手动排盘**：必须通过 iztro 代码执行，手动推算几乎必然出错
- **混用体系不标注**：冲突处必须标注来源，不能悄悄混用
- **亮度混淆**：iztro七级 vs 倪师三级，映射：庙旺→庙旺，得利平→平，不陷→陷
- **大限四化误用**：倪师体系不使用，综合模式必须标注
- **宫干自化误用**：倪师不主张，综合模式标注"供参考"
- **空宫忘借对宫**：遗漏会导致严重误判
- **编造断语**：不确定的如实说，无法追溯的标注"AI推断"
- **讨好倾向**：凶象如实描述，格局不成立就不成格
- **夫妻宫断语遗漏**：武曲/廉贞/七杀/破军在夫妻宫一律建议晚婚
