# 多时辰对比策略

## 核心理念

多时辰对比的目标不是"排除不像的"，而是"找到最像的"。排除只能基于事件验证得分，不能基于性格自述。

## 数据提取（基于 astro.js 输出）

排盘命令输出 `output-schema.md` 中定义的结构化 JSON。关键提取路径：

| 维度 | 提取路径 | 影响程度 |
|------|---------|---------|
| 命宫主星+亮度 | `soulPalaceInfo.majorStars[0].name` + `.brightness` | 🔴 决定性 |
| 命宫地支 | `soulPalaceInfo.earthlyBranch` | 🔴 决定性 |
| 身宫位置+主星 | `bodyPalaceInfo.name` + `.majorStars` | 🟡 重大 |
| 化禄落宫 | `birthMutagens` 中 `mutagen="禄"` 的 `palace` + `star` | 🟡 重大 |
| 化忌落宫 | `birthMutagens` 中 `mutagen="忌"` 的 `palace` + `star` | 🟡 重大 |
| 来因宫 | `basicInfo.originalPalace.name` | 🟡 重大 |
| 大限走向 | `decadalList`（按 `palaceIndex` 顺序即为大限走向） | 🟡 重大 |
| 当前大限 | 见 `calibration-protocol.md` 2.7 节 | 🟡 重大 |

## 对比策略

### 策略1：全量排盘（候选时辰 ≤6 个时使用）

为每个候选时辰完整排盘，提取以上 7 个关键维度做对比表。

### 策略2：快速筛选+深度对比（候选时辰 >6 个时使用）

**第一步：快速筛选**

只为每个候选时辰提取命宫主星（`soulPalaceInfo.majorStars[0].name`），结合行为模式问卷给出辅助参考分。

⚠️ 快速筛选**不排除任何时辰**，只标记"问卷倾向"。

**第二步：深度对比**

对全部候选时辰（不是只对"倾向"的时辰）进行完整排盘对比。

### 策略3：事件验证对比（核心步骤）

对所有候选时辰逐一验证事件吻合度。

1. 用 `--year` 参数获取流年数据：

```bash
node scripts/astro.js "YYYY-M-D" hourIndex gender --year YYYY
```

2. 检查 `yearlyData.yearlyMutagens` 和 `yearlyData.decadalMutagens`
3. 按 `calibration-protocol.md` 2.10 节的评分规则打分

## 性格描述规范

### 禁止的描述方式

| ❌ 禁止 | 原因 |
|---------|------|
| "天府=保守" | 太刻板，天府人也可以很活跃 |
| "七杀=冲动" | 太负面，七杀也可以是果断 |
| "天同=懒" | 太简化，天同是享受生活不是懒 |
| "你是开创型" | 抽象标签，用户无法准确自评 |

### 要求的描述方式

每个时辰的性格描述必须包含以下结构：

```
【{时辰}】{命宫主星}坐命
- 天命本底（小时候更明显）：
  · 做事风格：{描述，如"喜欢先做了再说，边做边调整"}
  · 社交方式：{描述，如"不太主动社交，但一旦熟了就很放得开"}
  · 情绪特点：{描述，如"情绪来得快去得快，不太记仇"}
- 当前大限影响（{当前大限宫位}，{起止年龄}岁）：
  {描述大限带来的偏移，如"当前走福德宫大限，心思比以前重了，容易想太多"}
- 正面：{描述，如"重情义，对朋友很仗义"}
- 容易踩坑：{描述，如"太重面子，有时候死撑不说"}
```

## 排除规则

### 可以排除的条件

1. 事件验证累计得分持续最低（比次低分低 ≥3 分）
2. 有 ≥2 个 A 类事件（感情、事业）与盘面明显矛盾（强矛盾标记）
3. 盘外验证 0 条命中且有其他候选时辰 ≥2 条命中

### 不可排除的条件

1. ❌ 用户说"这个性格不像我" → 性格自述不可靠
2. ❌ 问卷参考分低 → 问卷只是辅助参考
3. ❌ 只有一个事件矛盾 → 可能是事件描述不够具体
4. ❌ 用户在第1轮没选该时段 → 时段选择已隐含排除，见 `calibration-protocol.md` 2.3 节

### 排除后的复核

如果排除了某个时辰，但后来发现剩余时辰的盘外验证全部失败，必须回溯：
1. 重新检查被排除时辰的事件验证
2. 确认排除理由是否充分
3. 如果排除理由不够充分，重新纳入候选
