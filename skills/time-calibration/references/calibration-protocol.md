# 反推时辰完整协议

本文档是反推时辰的**唯一协议权威来源**。SKILL.md 中的固定输出模板必须与本文档的规则保持一致。

## 一、核心原则

1. **事件验证是唯一可靠的排除依据**：性格自述、主观感受不可靠，只有可验证的客观人生事件才能用于排除时辰
2. **性格会变，天命不变**：紫微斗数算的是天命（先天格局），性格表现随大限流年变化。小时候的性格更接近天命本底
3. **所有候选时辰必须全程参与评分**：不能因为用户"觉得不像"就跳过某个时辰
4. **排盘必须用代码**：所有排盘通过 `scripts/astro.js` 执行，禁止手动推算
5. **结论带置信度**：反推时辰是概率推断，不是确定答案
6. **产出隔离**：反推完成后，用户应在新的对话中排盘分析
7. **提问要具体**：问具体行为和事件，不问抽象标签

## 二、反推流程（4轮）

### 第1轮：收集基础信息 + 时段选择 + 行为模式问卷

#### 2.1 必须收集

- 阳历出生日期（年月日）
- 性别
- 出生地点（城市名或经度，用于真太阳时换算）

**不知道出生地的处理**：
- 如果用户不知道出生地，无法换算真太阳时，使用时钟时辰
- 需在结论中标注"未使用真太阳时换算，结果可能存在偏差"
- 提醒用户：出生地越偏西（如四川、云南、新疆、西藏），偏差越大

#### 2.2 可选收集

- 无

#### 2.3 时段选择

##### 时段与时辰对应关系

| 时段 | 时间范围 | 对应时辰 | hourIndex |
|------|---------|---------|-----------|
| 深夜/凌晨 | 23:00~03:00 | 晚子时(12)、早子时(0)、丑时(1) | 12, 0, 1 |
| 清晨/早上 | 03:00~09:00 | 寅时(2)、卯时(3)、辰时(4) | 2, 3, 4 |
| 上午 | 09:00~11:00 | 巳时(5) | 5 |
| 中午 | 11:00~13:00 | 午时(6) | 6 |
| 下午 | 13:00~17:00 | 未时(7)、申时(8) | 7, 8 |
| 傍晚/晚上 | 17:00~23:00 | 酉时(9)、戌时(10)、亥时(11) | 9, 10, 11 |

##### 候选时辰确定规则

| 用户选择 | 处理方式 |
|---------|---------|
| 选了1个时段 | 该时段内所有时辰为候选 |
| 选了2-3个时段 | 合并所有选中时段的时辰为候选 |
| 选了4个以上时段 | 建议用户缩小范围；若用户坚持无法缩小，则全部选中时段为候选 |
| "完全不记得" | 全部13个时辰（早子时~亥时+晚子时）为候选 |

##### ⚠️ "候选时辰" vs "已排除时辰"的明确语义

- **候选时辰** = 用户选中时段内的所有时辰。这是第2轮和第3轮必须全程参与排盘和评分的对象。
- **已排除时辰** = 用户未选中时段内的所有时辰。这些时辰在第1轮之后**不再参与后续验证**，因为用户对出生时段的记忆是最可靠的缩小范围依据。
- 如果用户选择"完全不记得"，则全部13个时辰均为候选，不存在已排除时辰。
- 时段选择是唯一基于用户主观信息的排除——它与性格排除不同，因为"我妈妈说我大概是下午生的"属于事实性信息而非主观判断。

##### 跨时段边界处理

以下情况需同时纳入相邻时段的时辰：

| 用户描述 | 处理 |
|---------|------|
| 选了"中午"但补充说"可能是12点左右" | 同时纳入午时(6)和未时(7) |
| 选了"深夜/凌晨"但补充说"可能是11点多" | 同时纳入亥时(11)和晚子时(12) |
| 选了"深夜/凌晨"但补充说"可能是凌晨1点左右" | 同时纳入丑时(1)和早子时(0) |
| 选了"傍晚/晚上"但补充说"可能是下午5点左右" | 同时纳入申时(8)和酉时(9) |
| 选了"清晨/早上"但补充说"可能是早上7点左右" | 同时纳入辰时(4)和巳时(5) |

#### 2.4 真太阳时换算（时段选择后必须执行）

用户选择时段后，必须对选中时段的边界时间运行 `solar-time.js` 换算真太阳时：

```bash
node scripts/solar-time.js <出生地> <时段起始时间HH:MM> --json
node scripts/solar-time.js <出生地> <时段结束时间HH:MM> --json
```

**候选时辰调整规则**：

| 真太阳时结果 | 处理 |
|------------|------|
| 真太阳时与时钟时辰一致 | 候选时辰不变 |
| 真太阳时比时钟时辰早（偏西） | 候选时辰向前调整，如时钟丑时→真太阳子时 |
| 真太阳时比时钟时辰晚（偏东） | 候选时辰向后调整，如时钟子时→真太阳丑时 |
| 边界时间跨时辰 | 两个时辰都纳入候选 |

**必须告知用户**：时钟时辰与真太阳时辰的差异，以及排盘将使用真太阳时。

#### 2.5 行为模式问卷

5道具体行为问题（固定题目见 SKILL.md），请用户回忆小时候（12岁以前）的行为模式。

##### 问卷计分方法

每道题根据用户选择的选项，对照各候选时辰的命宫主星进行匹配计分：

**步骤1：为每道题确定倾向星曜组**

| 题号 | 选项A倾向 | 选项B倾向 | 选项C倾向 |
|------|----------|----------|----------|
| 1（做决定） | 杀破狼系（七杀/破军/贪狼/廉贞/武曲） | 紫府系（紫微/天府/天相/太阳） | 机月同梁系（天机/太阴/天同/天梁） |
| 2（社交） | 杀破狼+太阳 | 太阴+天同+天梁 | 混合型 |
| 3（遇不公平） | 七杀/破军/廉贞/武曲 | 天同/天相/天府 | 天机/太阴/天梁 |
| 4（规矩计划） | 杀破狼系 | 紫府系 | 机月同梁系 |
| 5（学校角色） | 七杀/紫微/破军 | 天同/天府/天相 | 太阴/天机/天梁 |

**星曜系别定义：**
- **杀破狼系**：七杀、破军、贪狼、廉贞、武曲
- **紫府系**：紫微、天府、天相、太阳
- **机月同梁系**：天机、太阴、天同、天梁

**步骤2：逐题匹配计分**

对每个候选时辰的命宫主星（取其第一个 majorStar 的名称），检查该主星是否在用户选项对应的倾向星曜组中：

- 在该组中 → 该候选时辰此题得 1 分
- 不在该组中 → 该候选时辰此题得 0 分

对于第2题选项C（混合型），所有候选时辰都得 1 分（不区分）。

**步骤3：计算问卷参考分**

问卷参考分 = 5道题得分之和（满分5分，最低0分）。

**步骤4：使用规则**

- 问卷参考分仅作为第2轮对比表中的"辅助参考分"展示
- 绝对不能根据问卷分排除任何候选时辰
- 如果某个候选时辰问卷得分显著偏低（≤1分），仅能在对比表中标注"问卷倾向度低"，但必须继续参与后续事件验证

### 第2轮：候选时辰排盘 + 多维度深度对比

#### 2.6 排盘步骤

1. 对每个候选时辰执行排盘命令：

```bash
node scripts/astro.js "YYYY-M-D" hourIndex gender
```

2. 从输出中提取关键维度数据（详见 `references/output-schema.md`）。

#### 2.7 对比维度提取

| 维度 | 提取路径 | 影响程度 |
|------|---------|---------|
| 命宫主星+亮度 | `soulPalaceInfo.majorStars[0]` | 🔴 决定性 |
| 命宫地支 | `soulPalaceInfo.earthlyBranch` | 🔴 决定性 |
| 身宫位置+主星 | `bodyPalaceInfo.name` + `.majorStars` | 🟡 重大 |
| 化禄落宫 | `birthMutagens` 中 mutagen="禄" | 🟡 重大 |
| 化忌落宫 | `birthMutagens` 中 mutagen="忌" | 🟡 重大 |
| 来因宫 | `basicInfo.originalPalace.name` | 🟡 重大 |
| 当前大限 | 见下方"当前大限计算" | 🟡 重大 |

#### 2.8 当前大限计算

1. 从 `decadalList` 获取所有大限范围（`range` 字段如 `"25~34"`）
2. 计算用户当前虚岁：虚岁 = 当前农历年 - 出生农历年 + 1
   - 若用户未过当年农历生日：虚岁 - 1
3. 从 `basicInfo.startingAge` 获取起运年龄
4. 匹配 age 落在哪个大限的 range 区间内
5. 获取该大限的 `palace`、`heavenlyStem`、`earthlyBranch`

**示例**：
- 用户出生于 1990 年农历四月廿一，当前为 2026 年
- 虚岁 = 2026 - 1990 + 1 = 37（若已过生日）
- `decadalList` 中有 `{"palace":"夫妻","range":"35~44",...}`
- 当前大限 = 夫妻宫，35~44 岁

#### 2.9 重要规则

- **不排除任何候选时辰**，只标记倾向
- 性格描述必须多角度、区分"天命本底"和"当前大限影响"、包含正反两面
- 详细性格描述模板见 `references/comparison-strategy.md`

### 第3轮：深度事件验证（核心步骤）

#### 2.10 验证步骤

1. **确定事件年份**：用户给出具体年份
2. **为每个候选时辰执行流年排盘**：

```bash
node scripts/astro.js "YYYY-M-D" hourIndex gender --year YYYY
```

3. **定位大限触发**：检查 `yearlyData.decadalMutagens`，找出该大限四化落入的宫位
4. **定位流年触发**：检查 `yearlyData.yearlyMutagens`，找出该年流年四化落入的宫位
5. **检查宫位相关性**：通过 `originPalaceName` 判断四化是否触发事件相关宫位
6. **检查四化方向**：化禄/化科 = 好事，化忌 = 坏事/变动，化权 = 主动变动
7. **检查事件强度**：多重四化叠加 = 强事件，单一四化 = 弱事件

#### 2.11 评分规则

| 匹配程度 | 得分 | 条件 |
|---------|------|------|
| 强匹配 | +2 | 事件性质 + 宫位 + 四化方向完全吻合 |
| 弱匹配 | +1 | 宫位对上但四化不完全吻合 |
| 矛盾 | -2 | 事件与盘面信号明显矛盾 |
| 无法判断 | 0 | 事件太模糊或信号不明确 |

#### 2.11 矛盾阈值规则

- **正常矛盾（-2 分）**：单一事件矛盾，继续观察后续事件
- **强矛盾标记（优先级最高）**：某个候选时辰在任意时刻累计有 **≥2 个 A 类事件（感情、事业）明显矛盾**，应标记为"强矛盾候选"，即使净得分不是最低也应优先考虑排除
- **判断标准**：A 类事件 = 感情（夫妻宫相关）和事业/学业（官禄宫相关）事件。健康、家庭、社交事件为 B 类，需 ≥3 个矛盾才触发强矛盾标记
- **应用**：强矛盾标记在排除决策中比单纯的得分差更优先

#### 2.12 强制规则

- 所有候选时辰必须参与事件验证，一个不能少
- 即使用户在第2轮说"某个时辰不像"，该时辰仍需参与第3轮评分
- 如果某个被标记"不像"的时辰事件验证得分反而最高，必须重新纳入并如实告知用户

#### 2.13 逐步排除规则

| 条件 | 操作 |
|------|------|
| 某时辰得分持续最低且比次低分低 ≥3 分 | 可以排除，需说明排除理由 |
| 某时辰被强矛盾标记（≥2 个 A 类矛盾） | 优先排除，即使得分不是最低 |
| 两个时辰得分差距 ≤2 分 | 不急于排除，增加验证事件 |
| 收集 ≥3 个事件后仍无法区分 | 进入第4轮，不做排除 |

#### 2.14 事件收集优先级

1. **先问感情和事业**（A 类强验证）：事件最明确，年份好确认
2. **再问家庭和健康**（A 类+B 类混合）：补充验证
3. **最后问社交**（B 类+C 类）：辅助参考

详细提问模板见 `references/event-palace-mapping.md`。

### 第4轮：结论 + 盘外验证

#### 2.15 盘外验证

从最可能时辰的命盘推导 2-3 条**未参与校准的预测断语**，请用户确认：

- 必须是具体、可验证的事件
- 必须是用户之前没有提过的领域
- 至少 2 条，最好 3 条

#### 2.16 置信度判定

| 置信度 | 条件 |
|--------|------|
| 高 | 事件验证得分最高时辰领先 ≥4 分 + 盘外验证 ≥2 条命中 |
| 中 | 事件验证得分最高时辰领先 2-3 分 + 盘外验证 ≥1 条命中 |
| 低 | 事件验证得分最高时辰领先 <2 分 或 盘外验证 0 条命中 |

#### 2.17 盘外验证失败处理

- 0 条命中 → 降级置信度一档
- 0 条命中 + 事件得分接近（≤2 分差）→ 给出 2-3 个最可能时辰及各自概率百分比

## 三、性格随大限变化的处理

| 阶段 | 大限影响 | 性格表现 |
|------|---------|---------|
| 小时候（第 1 大限） | 刚起运，影响小 | 最接近天命本底 |
| 青年（第 2-3 大限） | 大限影响逐渐增强 | 天命+大限叠加 |
| 中年以后 | 大限影响显著 | 可能与天命本底差异大 |

处理方式：
1. **问小时候**：12 岁以前的行为模式更接近天命本底
2. **标注大限影响**：在性格描述中区分"天命本底"和"当前大限偏移"
3. **不因性格变化排除**：用户说"我现在不是这样的"不代表时辰不对

## 四、特殊情况

### 4.1 跨日时辰

晚上 23:00 后出生可能涉及早子时/晚子时问题。astro.js 支持 hourIndex=0（早子时）和 hourIndex=12（晚子时）。跨日时需同时排两个子时盘对比。

### 4.2 真太阳时

**默认使用真太阳时。** 北京时间基于东经120°标准时，但不同经度的地区真太阳时不同。排盘应以真太阳时为准。

**换算方法**：

```bash
node scripts/solar-time.js <出生地或经度> <时钟时间HH:MM> [--json]
```

**关键规则**：
- 排盘时必须使用真太阳时对应的 hourIndex，而非时钟时辰的 hourIndex
- 经度偏移 = (出生地经度 - 120) × 4 分钟
- 中国西部地区偏移较大：成都约-64分钟、昆明约-93分钟、乌鲁木齐约-130分钟、拉萨约-116分钟
- 偏移超过60分钟时，真太阳时时辰可能与时钟时辰差1个；超过120分钟可能差2个

**时段选择后的换算流程**：
1. 用户基于记忆（北京时间）选择时段
2. 对选中时段的边界时间运行 `solar-time.js` 换算
3. 以真太阳时对应的时辰作为候选时辰
4. 在输出中明确告知用户"时钟时辰"与"真太阳时辰"的差异

**不知道出生地的处理**：
- 无法换算真太阳时，使用时钟时辰
- 需在结论中标注"未使用真太阳时换算，结果可能存在偏差"
- 提醒用户：出生地越偏西，偏差越大

### 4.3 完全无线索

用户完全不知道出生时间且无任何线索时：
1. 先排全部 13 个时辰的命宫主星对比表
2. 结合行为模式问卷给出辅助参考
3. 进入深度事件验证

### 4.4 反推失败

如果 4 轮对话后仍无法确定时辰：
1. 给出 2-3 个最可能时辰及其概率
2. 建议用户选择"最可能"的时辰进行排盘
3. 提醒排盘报告中标注"时辰为推断，部分结论需谨慎"

## 五、常见陷阱

| 优先级 | 陷阱 | 正确做法 |
|--------|------|---------|
| 🔴 高 | 手动排盘 | 必须通过 astro.js 代码执行 |
| 🔴 高 | 反推信息带入排盘分析 | 反推完成后必须在新对话中排盘 |
| 🔴 高 | 过度承诺时辰准确性 | 结论必须带置信度，低置信度要明确说 |
| 🔴 高 | 根据性格自述排除时辰 | 性格描述只能标记"倾向"，不能排除。所有候选时辰必须参与事件验证 |
| 🔴 高 | 事件验证不覆盖所有候选 | 即使用户说"不像"，该时辰仍需参与事件评分 |
| 🔴 高 | 性格描述太刻板 | 必须多角度描述，区分天命本底和大限影响 |
| 🔴 高 | 提问太抽象 | 问具体行为，不问抽象标签 |
| 🔴 高 | 事件验证不执行流年排盘 | 必须用 `--year` 参数获取流年四化数据 |
| 🔴 高 | 忽略真太阳时换算 | 排盘必须使用真太阳时 hourIndex，西部地区可能差1-2个时辰 |
| 🟡 中 | 事件验证只看四化不看宫位 | 必须同时检查宫位触发和四化方向 |
| 🟡 中 | 引导性提问 | "你哪一年结的婚？" 而不是 "你是不是 2018 年结的婚？" |
| 🟡 中 | 忽略性格随大限变化 | 问小时候的行为模式，标注大限影响 |
| 🟡 中 | 忽略矛盾阈值 | 累计 ≥2 个 A 类矛盾时必须优先标记 |
| 🟢 低 | 忽略跨日时辰 | 23:00 后需考虑早子时/晚子时 |
| 🟢 低 | 忽略跨时段边界 | 用户说"大概 X 点左右"时应纳入相邻时辰 |
