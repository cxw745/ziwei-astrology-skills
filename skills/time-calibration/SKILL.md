# 紫微斗数反推时辰

## 核心原则

1. **事件验证是唯一可靠的排除依据**——性格自述、主观感受不可靠，只有可验证的客观人生事件才能用于排除时辰
2. **性格会变，天命不变**——紫微斗数算的是天命（先天格局），性格表现随大限流年变化。小时候的性格更接近天命本底，成年后受大限影响会偏移
3. **所有候选时辰必须全程参与评分**——不能因为用户"觉得不像"就跳过某个时辰。用户的主观排除是最不可靠的信号
4. **排盘必须用代码**——所有排盘通过 `scripts/astro.js` 执行，禁止手动推算
5. **结论带置信度**——反推时辰是概率推断，不是确定答案
6. **产出隔离**——反推完成后，用户应使用新的对话去排盘分析。反推过程中用户透露的人生经历不应被带入命盘分析
7. **不讨好不编造**——不确定就说不确定，不为了给用户一个"答案"而强行判断
8. **提问要具体**——问"做决定时你更冲动还是深思熟虑"而不是"你是开创型还是保守型"

## 排盘命令

```bash
# 基础排盘（反推时辰必须使用此命令）
node scripts/astro.js "YYYY-M-D" hourIndex gender

# 带流年排盘（第3轮事件验证时使用）
node scripts/astro.js "YYYY-M-D" hourIndex gender --year YYYY
```

- `hourIndex`：0=早子时, 1=丑时, ..., 11=亥时, 12=晚子时
- `gender`："男" 或 "女"
- 时辰映射详见 `references/time-mapping.md`
- 输出数据结构详见 `references/output-schema.md`

### 真太阳时换算

```bash
node scripts/solar-time.js <出生地或经度> <时钟时间HH:MM> [--json]
```

- 出生地：城市名（如"成都"）或经度（如104.1）
- 时钟时间：北京时间，HH:MM格式
- `--json`：输出JSON格式，关键字段：`solarBranch`（真太阳时hourIndex）、`changed`（是否与时钟时辰不同）
- **排盘时必须使用真太阳时对应的hourIndex，而非时钟时辰**

## 工作流（4轮）

完整的流程、协议、评分规则见 `references/calibration-protocol.md`。
以下为每轮必须使用的固定**用户可见**输出模板。

### 第1轮：收集基础信息 + 时段选择 + 行为模式问卷

#### 时段选择固定输出

| 时辰 | 时间范围 | 对应时段 |

👉 请选择可能的时段（可多选）：
  □ 深夜/凌晨（23:00~03:00）

#### 真太阳时换算（时段选择回答后必须执行）

用户回答时段选择后，必须运行 `solar-time.js` 换算真太阳时：

```bash
# 对用户选择的每个时段边界时间运行换算
node scripts/solar-time.js <出生地> <时段起始时间HH:MM> --json
node scripts/solar-time.js <出生地> <时段结束时间HH:MM> --json
```

固定输出模板：

```

|-------------------|---------|---------|-----------|
| {时段起始} | {换算后} | {时辰} | {时辰} |
| {时段结束} | {换算后} | {时辰} | {时辰} |

{如果真太阳时与时钟时辰不同：}
⚠️ 真太阳时时辰与时钟时辰不同！排盘将以真太阳时为准。

📌 候选时辰（基于真太阳时）：{列出真太阳时对应的时辰名及时间范围}
```
